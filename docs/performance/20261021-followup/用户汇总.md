# WEBRC505MKII 性能增量报告：2026-10-21 续批

本轮基线为 `eb60b801e3842e72d5584d191b00e68d6fc3caed`，不是最早性能基线。下面百分比均为本轮增量，不能与上批百分比直接相加。最终提交见 Git 提交及交付回执。

## 本轮五个定位结果

1. Browser Gate Reverb 包络控制派生量在平滑结束后仍逐样本重复 pow/round/exp。专项 V8 自采样占比 6.24%，精确缓存后降至 2.88%；这是归因诊断，不是整机 CPU 百分比。
2. Browser TREMOLO/AUTO PAN 在旧/目标波形相同时重复求同一个纯 LFO。专项 lfoValue 自采样占比 22.50%→14.19%；保留原插值算式避免改变舍入。
3. Native PREAMP 即使 mono 输入也计算无历史的全零右声道。已增加严格正零初态捷径；任意非零或负零输入后直到 reset 都恢复原处理，不截断尾音，平滑器仍逐帧推进。
4. Native 非零重载仍以 PREAMP 非线性和 ROBOT 分析为主要成本。保持加法顺序的 SSE2 YIN 候选实际五轨图两序 mean 仅 −0.15%/+0.30%，拒绝；不能把尾分位波动当可靠收益。
5. 真实 Browser 全图、调度、GC/IPC 仍是测量缺口。现有云浏览器只允许可达 HTTP(S) 入口，本地 file URL 被拒绝后未绕过。Node VM bundled DSP 数据不是实际 AudioWorklet 回调结果。

Native 为48k/64帧、CPU0、每run8000回调、ABBA+BAAB各两次/版本。该单Input PREAMP场景的 mean(run p99) 268.827→208.306 µs，所有run最大观测 4.075→3.143 ms，峰值RSS均值均为9424 KiB；32000回调中CPU超预算计数32→5。虽然均值有收益，最大值仍不达1.333ms总预算及80%目标，不能报告实时PASS。此处 p99 是各run p99均值，不是合并回调总体p99。硬件XRUN未知，不能写0。

Native stereo Input场景没有确认收益；完整五轨stereo重载两序mean变化+0.33%/−2.61%，无实质改善。上述19.53%不得外推五轨重载。

## 正确性与拒绝的假设

- Gate长流16/16、条件构造后的短流16/16均PCM逐字节相同；LFO波形切换/reset/bypass24/24，以及正式四组性能流全部PCM相同。
- Native右零初态75组覆盖8/44.1/48/96/192k、五模型、mono/stereo/额外通道、首次输入、自动化、reset、负零/非有限/subnormal；PCM逐字节一致。
- 三段FIR连续span候选：automation+3.59%、sine−1.08%、silence−12.82%，拒绝。
- SSE2 YIN候选：音频与pitch状态18组一致，但整图无可靠收益，拒绝；未合入架构特化代码。
- 左零初态扩展：100组PCM一致，但活动负载无净收益、mono自动化平均回退约3%且次序不稳定；即使全初始静音极快仍拒绝。未把边缘case收益包装成通用优化。
- 无降采样、降低过采样、fast-math、近似非线性、改变滤波器/分析周期或UI覆盖。
