# 第二轮软件音频优化：实测结果

本轮由 gpt-6-luna / max 执行，主代理规划、复核并串行完成最终测量。范围是软件；没有打开物理输入、进行声卡回环或更改设备路由。

## 结果

| 指标 | 用户引用的原记录 | 最终版本实测 |
| --- | ---: | ---: |
| Compressor 算法附加缓冲延迟 | 6 ms | 0 帧：44.1、48、96 kHz 离线测量；48 kHz Chromium 合成输入实时测量也为 0 帧 |
| 五轨 Looper 模拟 process() P99 | 0.0451 ms | 0.0209 ms，约下降 54% |
| 五轨 Looper 模拟 process() Max | 10.8498 ms | 1.1235 ms，该次约下降 90% |
| 五轨模拟 process() 超过 2.6667 ms 预算次数 | 17 | 0 |

最后三行都是 Node/V8 VM 调用真实 Looper 源码的执行耗时，未包含 Compressor 或整个浏览器音频图。它们不是音频到达延迟、播放量化等待时间、硬件 RTL 或硬件 XRUN。原记录和最终测量都是 48 kHz / 128 帧、五轨播放、675,000 次调用；最终测量增加了 GC 时间戳观测，不能把单次 Max 的变化解释为未来峰值保证。

Compressor 用无前瞻的立体声联动 Worklet 替换内置 DynamicsCompressorNode，去掉其固定 6 ms 前瞻缓冲。新算法没有自动补偿增益，压缩曲线、响度和瞬态处理会改变，不能保证与旧算法同音色。attack/release 控制幅度响应速度，不能当作信号缓冲延迟。详见 [Compressor 实测与取舍](SOFTWARE_OPTIMIZATION_20261007.md)。

Looper 稳定播放时把轨道数据、输出、长度、位置和方向缓存到构造时分配的数组，减少逐样本读取和分支；无待执行命令时跳过命令扫描。最终快路径覆盖 1–5 条 PLAYING 轨和 EMPTY/STOPPED 混合，并允许时钟运行。空轨和停止轨输出 0，不读残留 PCM。录制、叠录、监听、校准、节奏及任何待执行命令均使用原逐样本路径，保持块内命令的采样帧精度。

## 最终串行复测

全部使用同一脚本、48 kHz / 128 帧、GC 观测、每 256 块让出主机 20 ms。计时只包围 `process()`；主机等待、断言、数据保存不计入单次耗时。测量期间没有并行构建或测试。

| 场景 | 回调数 | P50 ms | P95 ms | P99 ms | Max ms | 模拟超时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧源码，单轨播放＋四空轨＋119 BPM 时钟 | 112,500 | 0.0127 | 0.0243 | 0.0322 | 3.2381 | 2 |
| 最终源码，相同单轨及时钟条件 | 112,500 | 0.0077 | 0.0136 | 0.0170 | 0.2917 | 0 |
| 最终源码，五轨播放、时钟关闭 | 675,000 | 0.0094 | 0.0162 | 0.0209 | 1.1235 | 0 |

单轨受控对比 P99 下降约 47%。两次各处理 5 分钟采样量，时钟各产生 595 个预期事件。最终五轨处理 86,400,000 帧，即 30 分钟音频采样量，实际 phase 循环耗时 81.7508 秒；它不是连续运行 30 分钟的浏览器或设备稳定性测试。3,375,000 次轨道相位检查、675,000 次绝对帧计数检查均无错误，跨低字计数边界 1 次，相位漂移 0 帧。

旧源码来自提交 `b12ae2f`，SHA-256 `f1295156101cecf7bd5ccc8b6d3cea0b10d6f0cde52eeda35b4d4a3ffd72f0a6`；最终 Looper 源码 SHA-256 `f960e6212baf045a4155d066355d6fa289468517c4a168e3d94f081b30de7d5a`。

## 验证、证据与复现

- 42/42 单元测试、类型检查、生产构建、3/3 UI 测试通过。
- Chromium 149 合成输入软件检查 19/19 通过，覆盖五轨录放/叠录、滤波、监听、校准失效及七条 FX 链初始化；[最终浏览器记录](measurements/software-browser-optimized-20261007.json)。
- 真实 Looper 源码断言覆盖正反播放逐样本一致、119 BPM 在 32 位低字边界处的精确 tick、块内命令、空轨/停止轨残留 PCM 静音、协议 ACK 和错误路径。UI mocks 不能代替这些音频断言。
- 全部七种 FX 额外完成 48 kHz 各五次离线测试；[结果 CSV](measurements/offline-all-fx-48k-optimized-20261007.csv) 分开记录首达、峰值、尾音和离线渲染耗时，后者不是实时 callback 耗时。
- [最终三次测量的压缩记录](measurements/worklet-optimized-final-20261007.trace.json) 保存完整分布摘要、源码哈希、未过滤原始样本文件的绝对路径及 SHA-256、复现命令。逐回调 CSV 留在所列 TEMP 路径；清理 TEMP 会删除这些原始文件。
- [可导入仪表盘的软件报告](measurements/software-worklet-optimized-20261007.json) 验证通过，仍为 `NOT_VERIFIED`；物理 RTL 和硬件 XRUN 保持未知。
