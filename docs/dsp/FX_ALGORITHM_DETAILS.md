# Implemented Browser FX algorithm details

All items below are clean-room functional implementations. They do not reproduce Roland source code, measured hardware response, or factory DSP topology. The catalog's official function names and stable source indices are metadata; internal algorithm choices below are authored/reconstructed.

## Processor/runtime shape

- The real Browser AudioWorklet is `rc505-fx-processor` from `public/worklets/fx-processor.js`; TypeScript DSP sources live in `src/audio/fx/dsp/BrowserFxDspCore.ts` and `src/audio/worklet/FxProcessor.ts`. `npm run build` regenerates the checked-in worklet bundle from the TypeScript entrypoint before Vite copies the public asset.
- The DSP processes the actual channel-array lengths provided to each callback and retains state across callbacks. It does not assume 128 frames.
- The tested core path writes into caller-owned buffers and preallocates its state. A live browser allocation trace has not been captured, so no whole-engine zero-GC claim is made.
- Bypass is the default. The FXBase wrapper initially retains a direct dry graph; after the module installs, processing is switched to the worklet, which receives current bypass and parameter values.
- `BrowserWorkletFX` instances are attachable to four dynamic input slots and four shared post-mix track slots. The routing unit test exercises adapters with mock graph nodes; DSP tests exercise real cores. Playwright E2E loads the shipped worklet in Chrome for Testing 154.0.8037.57 and renders VIBRATO, REVERSE DELAY, FREEZE, and experimental WARP in `OfflineAudioContext`; checks include finite/non-silent output, reversed stereo impulses, captured-vs-live tone suppression, and WARP output after capture. These are software-functional checks, not physical audio, live callback deadlines, whole-graph allocation behavior, or sound-quality acceptance.

## Not accepted or not implemented

- Current implementation-status counts are 45 implemented, 7 experimental and 1 catalog-only. The 45 implemented effects are wired in both runtimes; Native's C++ catalog has 51 executable descriptors (45 mapped implemented plus 6 experimental), while the Browser has 45 implemented and 7 experimental worklet routes. Native Input supports 42 implemented plus 5 experimental FX; its Track bank supports 45 plus 6. ELECTRIC remains catalog-only and BEAT SHIFT is Browser-only. OSC VOC (M) and OSC BOT are now represented as Native implementations as well as Browser routes; their clean-room voice/topology differences and lack of quality acceptance remain explicit. No effect has passed the full sound-quality admission gate. FREEZE remains micro-loop varispeed with spectral mode rejected; WARP spectral mode is also explicitly unsupported. Native has five independent stereo loopers, but catalog Track A–D FX remain post-mix; KeepPitch is separately selectable by global bus or one loop ID 1–5.
- Native rhythm DSP has 240 metadata patterns, 16 procedural clean-room kit timbres and sample-clocked callback scheduling. `/v1/native-rhythm/config` validates and reports enabled state, BPM, pattern, kit, variation, section, swing, quantize grid and volume. The Native TypeScript adapter serializes edits against host ACKs, and both UI panels share the same state. Browser and Native UI paths are software-tested; Native event sequences remain procedural and do not claim factory MIDI/sample fidelity.
- Native now checks five-track stereo loop storage against a 768 MiB budget before allocating and page-touching the full 300-second Float32 capacity. The 48 kHz configuration remains 300 seconds at 576,000,000 bytes. A rate requiring more than the budget is rejected with the maximum duration supported at that rate and a lower-rate instruction, rather than silently shortening the existing loop duration; the budget allows 209 seconds at 96 kHz or 104 seconds at 192 kHz. Status reports the duration, committed bytes, and budget. Memory is not pinned against OS paging, and no Native callback-tail or XRUN evidence exists.
- No final 53-FX serialization/preset automation, per-loop-track target routing, or 5×4 resource admission exists yet.
- The Browser headless AudioWorklet run executed for 1,800 real-wall seconds and passed a software-functional subcheck, but callback timing used a 1 ms-floor clock so CPU/P99/P99.9 acceptance is unmeasured. No Native hardware XRUN, physical audio endpoint, acoustic latency, or objective sound-quality dataset is available; see the raw stress report in `bench/results/gate7-browser-production-2026-10-17/`.
- Catalog status and algorithm detail status are not the same as full contract completion: parameter serialization, preset automation, per-loop-track target selection, and device performance admission remain incomplete.
