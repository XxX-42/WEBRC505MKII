# Browser loop transport routing status

BEAT SHIFT and VINYL FLICK currently use an experimental source-aware read-head in each `TrackAudio`. The shared Track A–D AudioWorklet adapter remains wired for catalog continuity but is forced to dry bypass, so these effects are not processed twice.

The legacy shared Track-bank adapter route runs before `TrackMix`. It is enabled only when no earlier active shared-bank A–D effect would need to run before it; a source effect can occupy A or the first active slot after empty or bypassed earlier slots. If an earlier shared-bank slot is active, that legacy source effect stays dry and `BrowserAudioEngine.getTrackTransportStatus()` reports its ordering reason. The dedicated per-track editor route is different: the source reader is always an upstream stage before that selected track’s private A→B→C→D chain. Arbitrary interleaving between that source stage and inserts is unsupported.

The Browser also has five independent pre-mix A→B→C→D insert chains. A source reader is a distinct upstream stage, not a selectable A–D insert, and does not implement arbitrary interleaving between transport and inserts. The legacy shared postmix bank remains as a compatibility route; do not treat it as the per-loop source reader.

When an individual track is selected in the Track FX panel, the separate Loop Source Transport editor exposes Browser/Native BEAT SHIFT and VINYL FLICK controls. Browser applies an explicit override to only that stored loop; opening the editor without a saved setting leaves the current route untouched, applying per-track Off is explicit, and a Browser-only control restores the shared Track FX source route. The editor stores these controls in runtime-specific browser local preferences, outside the PCM project archive.

The project-defined VINYL contract is target rate `clamp(1 + speedPercent/100, 0, 2)`, independent of mix; -100%, 0%, and +100% target 0×, 1×, and 2×. Mix is a linear dry/wet blend between canonical 1× playback and the motor-driven read head. Browser uses two `AudioBufferSource` nodes sharing the stored PCM, with separate gains, upstream of that loop's inserts. The Browser motor uses an analytic rate curve with Native-aligned target/return/brake parameters; Native advances its motor per callback sample, so the transient trajectories are not sample-exact peers. Source transitions use a bounded 1–10 ms crossfade. This duration is not the algorithmic latency or end-to-end latency, neither of which is measured. Real AudioContext spectral checks exercise Browser speed/mix behavior; this is software-functional evidence, not hardware or acoustic-quality acceptance.

Browser overdub writes canonical loop-frame indices, so its read-head is suspended during overdub and restored after the final worklet acknowledgment. Source-transport edits are rejected while that writer is active. This is deliberately narrower than live overdubbing through an independently moving read head. Treat both source-reader modes as experimental and partial.

Per-track reverse, LIVE_MONO, and LIVE_POLY conflicts are exposed by the same status API through each track's `unavailableReason`. The source-aware read-head currently requires forward BufferSource playback without either live pitch route.
