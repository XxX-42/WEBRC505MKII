## Runtime integration and acceptance boundary

The per-track chain implementation is a distinct route from the legacy shared Track bank described in the effect-by-effect algorithm table below. Browser's real route is `TrackAudio → private A→B→C→D worklet chain → TrackMix`; its coverage matrix explicitly accepts 43 of the 53 catalog descriptors and rejects ten unsupported host/MIDI/transport adapters without a silent shared-bank fallback. Native's route is `LooperCore playback → private Native A→B→C→D bank → sum`; the host exposes per-track bank availability and per-effect insert capability, validates 1-based target IDs, and publishes requested/applied revisions and processor faults. Both runtimes retain the shared postmix chain for compatibility. These routes have focused automated tests, but remain below the contract's realtime and sound-quality acceptance gates.

- `BrowserWorkletFX` is an `FXBase` adapter for `/worklets/fx-processor.js`. The existing dynamic bank chainers insert each wired worklet effect in order and send macro/bypass messages. The worklet processes the actual callback channel-array length, not an assumed 128 frames.
- Native UI wiring uses the generic `/v1/native-fx/catalog-slot` adapter for Input and Track A–D. It derives displayed options from the live `catalogEffectAvailability` and implemented ID list, sends persisted selections after device config but before engine start, and labels successful host responses as API ACKs. PREAMP has a six-control editor for model/gain/bass/middle/treble/level in classic and compact shells; STEP SLICER has its dedicated editor for sequence and step count/rate/depth/pan/filter parameters. Browser ROLL has a four-control editor for slice/decay/pitch/direction, explicit activation, persisted per-slot settings, and actual worklet parameter routing; other effects use a generic 0–100 macro, not an editor for every catalog parameter. A changed effect type cannot hot-swap while running; it stays pending until the Native engine is restarted. Current C++ status reports slot/effect/bypass state but not effective DSP parameter values, so the ACK confirms host acceptance/queueing rather than measured callback application.
- `tests/unit/browser-fx-bank-routing.spec.ts` checks serial slots and control messages in both banks using mock Web Audio nodes. Core/worklet tests exercise arbitrary block sizes, bypass, parameter stability, and algorithm behavior. They do not establish live browser render, XRUN, full-graph CPU, P99/P99.9, or sound-quality acceptance.
- FREEZE verification on 2026-10-17: `npm run build` passed; Browser unit suite passed 65 files / 377 tests; Chrome for Testing headless-shell Playwright passed FREEZE tech-shell control/persistence and shipped AudioWorklet capture/hold E2Es, 2/2. Native FREEZE processor, catalog, and route CTest passed 3/3, and test-only Native HTTP simulation passed 1/1; the complete portable runner was re-run after these changes and its current result is recorded in `IMPLEMENTATION_PROGRESS.md`. These software checks do not establish acoustic quality, hardware XRUN, callback deadline, or real-time P99 acceptance.
- DIST uses 4× sinc/ADAA rather than 1× naive saturation; DELAY/CHORUS/FLANGER use fractional delay reads. These implementation choices do not imply full matrix completion.
- Before ROLL integration, Native portable Debug CTest passed 33/33; the updated portable runner now passes with ROLL processor/factory/catalog/route coverage, while a fresh overall CTest total has not been recounted. A separate `NATIVE_BRIDGE_SIMULATION_ONLY=ON` HTTP test target is route simulation only; its fake callback source is not device, XRUN, timing, audio-quality, or real-time evidence. The cached-source regular Linux host build remains a distinct compiled host check and is not physical-device or real-time evidence.
- Native has five independent stereo `LooperCore` instances. `prepare` checks the requested 300-second buffers against a 768 MiB aggregate budget before allocation, then sizes and explicitly page-touches every accepted loop on the control thread; recording writes into prepared samples rather than growing vectors in the callback. At 48 kHz this retains the full 300 seconds (576,000,000 bytes). Rates requiring more storage are rejected with a clear lower-rate instruction and supported-duration estimate, never silently shortened; status reports max duration, committed bytes and budget. This avoids lazy first-touch on the record callback, but RAM is not pinned against OS paging, actual allocation failure/device pressure has not been measured, and no Native callback-tail or hardware XRUN pass is claimed.
- Native per-track level routing remains unsupported. Five tracks are separate transports/snapshots, and both runtimes now expose independent pre-mix five-track × four-slot FX chains while retaining the legacy shared postmix bank. KeepPitch is distinct: its Native adapter accepts trackId 0 for global playback or one loop ID 1–5, then routes only that selected loop through LIVE_MONO/LIVE_POLY before mixing. Browser TrackAudio owns a per-loop LIVE_MONO node. These are functional software routes, not realtime or hardware-quality acceptance.
- Native and Browser per-track chain controls have target selection, persistence, validation, status, and tests. Browser per-track selection explicitly rejects types without an admitted insert adapter; Native insert capability is host-reported. Coverage of the route does not imply every effect has complete controls or sound-quality acceptance. No adaptive quality tier or full per-FX quality admission exists. The 30-minute Browser headless-shell run passed its software-functional subcheck only; because it used a 1 ms-floor clock, P99/P99.9 and CPU-budget acceptance are unmeasured. Native hardware XRUN, acoustic latency, and full-app/device acceptance remain unverified. See `bench/results/gate7-browser-production-2026-10-17/REPORT.md` and raw data.
- Clean-room effects are not original Roland firmware, factory DSP topology, measured IRs or factory assets.
