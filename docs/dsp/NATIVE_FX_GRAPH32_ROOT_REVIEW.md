# Native prepared FX graph and 32-processor checkpoint

The shared factory now constructs 32 distinct supported processors. The Native host runs Input FX before recording, independent Track FX before gain/pan/mix, and Master FX after summing. Slot configuration, bounded timestamped automation and graph replacement are available through the in-process API. Native HTTP/UI FX configuration is still missing, and the host rejects Send inserts until an actual send-source route exists. This checkpoint does not establish 49/53 feature parity.

Graph admission accounts for fixed host/history memory, active and staged processor state, prepare scratch, alignment rings and retiring state. The old graph remains charged until `reclaimRetired()` destroys it on the control thread; audio callbacks neither allocate nor destroy it. Producer generation/order validation and coupled control validation reject invalid transactions.

Initial installation and replacement retain dry/previous audio while the candidate warms, then crossfade. The corrected warmup sums serial slots and conservatively bounds Input→Track→Master and Send→Master routes. Two/four Vinyl slots and Track→Master cascades are tested with DC and 55 Hz input on both channels, including replacement and clearing. These fixtures check sample-step bounds; they do not establish click-free behavior for all future effects or all material. The current alignment admission table must be extended when additional latent processors/profiles are integrated.
