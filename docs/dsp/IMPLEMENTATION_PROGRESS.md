## Current implementation snapshot

- The source catalog has 53 effect descriptors, 49 Input-capable and 53 Track-capable, with four Track-only effects. The status matrix counts 46 effects as implemented and 7 as experimental. Those counts indicate runtime code status, not quality admission.
- Browser has 46 matrix-implemented effects plus 7 experimental routes. Native C++ has 52 executable catalog descriptors: 46 mapped as implemented and 6 experimental. Native Input routes 43 implemented + 5 experimental effects; the shared Track bank routes 46 + 6. ELECTRIC (17) is now implemented in both runtimes. Native BEAT SHIFT still has no A–D catalog processor; its source-aware read-head API is separate from the catalog. These counts do not imply that every control is exposed or that audio has been quality-accepted.
- WARP (42) now has experimental Native and Browser A–D processors: bounded tempo-sized stereo capture, eight Hann grains and an FDN8 tail; spectral mode is explicitly rejected. Browser's shipped AudioWorklet E2E and Native processor/catalog tests establish software-functional output and routing only.
- TWIST (43) now has Native and Browser A–D DSP routes with four authored trajectory curves. The controls and behavior are clean-room/provisional because the supplied matrix CSV is unavailable; no recovered factory law or sound-quality acceptance is claimed.
- ROBOT (16) remains experimental. Native uses fixed-memory TD-PSOLA for admitted stable monophonic sources and Signalsmith fallback for unsupported sources/formant control. Browser has a PSOLA-lite path with Signalsmith fallback. The analyses and algorithm latency are not a measured end-to-end acoustic latency, and neither route separates polyphonic sources.
- KeepPitch and the FX banks are distinct. Native LIVE_MONO/LIVE_POLY can select global playback or one loop before mixing; Browser TrackAudio owns a LIVE_MONO node per loop. The current uncommitted delta adds five independent ordered A→B→C→D DSP banks before TrackMix/summing on both runtimes, plus separate UI/persistence and host ACK/status paths. Browser has an explicit 53-entry per-track matrix: 43 executable DSP types and 10 explicit rejects (including transport and unimplemented MIDI/host adapters). Native advertises per-track inserts from the host catalog except VINYL FLICK and source-aware BEAT SHIFT, which are explicitly rejected from A–D and kept separate. The old shared postmix bank is preserved. Transport-stage ordering with A–D remains unsupported, per-loop level routing is still absent, and no per-effect quality admission is claimed.
- HQ_RENDER WAV export uses the pinned MIT Signalsmith renderer and Worker for Browser mode. In Native mode the UI requests a callback-pinned loop snapshot description, then calls the optional C++ Rubber Band R2/R3 offline endpoint and encodes PCM16/PCM24/Float32 WAV. If Native Rubber Band was not enabled when built, capability is explicitly unavailable and the endpoint rejects the request; it never silently falls back to Signalsmith. The selected first-party license is GPL-3.0-or-later, and the optional Rubber Band v4.0.0 dependency is GPL-2.0-or-later; exact license files and reproducible build instructions are included.
- The Native HTTP host binds to `127.0.0.1:17755`, allows browser requests only from the project's exact localhost UI origins, rejects missing/foreign Origin on writes, and grants preflight only for GET/POST with Content-Type and no credentials. HTTP simulation tests assert one CORS origin header and that foreign or Origin-less writes do not mutate state.
- Native C++ rhythm now exposes a validated config/status HTTP route for enabled state, BPM, pattern, kit, variation, section, swing, quantize grid, and volume. The TypeScript Native adapter requires a healthy bridge and complete status, serializes commands against ACK state, and surfaces failures; both rhythm-control panels share acknowledged settings and playback state. Native generation remains procedural clean-room audio driven by metadata, not factory MIDI or samples.

## Update: Browser live Signalsmith WASM budget (2026-10-18 worktree)

The current worktree adds a per-`AudioContext` reservation ledger for each live Signalsmith Worklet. The ledger reserves the role maximum before module creation, retains the incumbent reservation while a candidate is preparing, and releases capacity only after a disposal acknowledgement or `AudioContext` closure. Unconfirmed release and pending creation remain visible in the Browser FX resource status. Per-instance ceilings are 20 WebAssembly pages (1.25 MiB) for LIVE_FX and 64 pages (4 MiB) for LIVE_POLY; the aggregate engineering policy is 128 MiB per context.

The maximum steady Browser graph is 28 A–D slots (four Input, four legacy shared-Track, and twenty per-track) × three LIVE_FX voices = 84 LIVE_FX reservations (105 MiB), plus five per-loop LIVE_POLY reservations (20 MiB), for 125 MiB total. Only 3 MiB remains for transitions in that worst case, so an oversized replacement is explicitly refused and the old route is kept. At 192 kHz, a shipped-Worklet CfT E2E exercises LIVE_FX at +24 semitones and LIVE_POLY at −24 semitones, 2× playback, the Nyquist tonality boundary, and stereo buffer loading. This is a WASM linear-memory limit and measured capacity report; it is not a cap on loop buffers, JavaScript memory, browser RSS, HQ rendering, or device realtime performance. The overall LIVE_POLY/HQ_RENDER performance and quality gates remain open.

Validation for this worktree: `npm run build` passed; the full Vitest suite passed 129 files / 907 tests; the strict Rubber Band E2E wrapper passed 84/84 tests serially with Chrome for Testing headless-shell 154.0.8037.57 and the explicit no-audio Native simulation host. The E2E includes the 192 kHz heap test and replacement rollback tests. These are software/simulation checks only; physical hardware, XRUN, browser-process RSS, callback P99/P99.9, and sound-quality acceptance remain unmeasured.
