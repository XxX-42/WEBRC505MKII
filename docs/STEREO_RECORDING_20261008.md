# 五轨真正立体声录音：实现与验证

浏览器模式的五轨现在独立保存、播放和叠录左右声道，不再将立体声输入平均为单声道。每轨导出的 AudioBuffer 也包含两个独立声道。反向播放、叠录位置补偿、录音起止量化和稳定播放快路径共用原有帧位置；帧长度仍表示每声道的帧数。

本次由 gpt-6-luna / max 执行生产实现和定向验证，主代理规划、复核并完成最终集成测试与串行长样本测量。范围是浏览器软件；原生端仍只有 Track 1 的基础功能，未做声卡或物理回环验收。

## 存储和兼容行为

- 每轨采用 planar LR：64 字节元数据之后，先存 `capacityFrames` 个左样本，再存同样数量的右样本；左右都是 Float32。
- 48 kHz、每轨 180 秒的容量保留。五轨 PCM 预分配合计 345,600,000 字节，约 329.6 MiB，另外还有元数据和控制区。
- 轨道元数据记录声道数 2、布局版本 2 和 planar LR 类型。Worklet 验证存储容量和布局，Runtime 验证附加确认消息；旧单声道确认消息不会使引擎误报立体声就绪。
- Worklet URL 带 `?layout=2`，区分旧单声道脚本缓存。附加失败或超时会清理缓存并允许重试；并发准备同一轨等待同一个附加操作。
- 输入源只有一个声道时复制到左右；两个声道时各自写入。请求采集时使用 `channelCount: { ideal: 2 }`，实际设备声道数仍按采集流设置报告，代码不会将单声道设备变成真实立体声源。
- 左右视图在轨道准备阶段分配，音频回调使用已有视图。CLEAR 仍只改变有效长度与状态，不扫描或清零整块 PCM；重录后只能播放新的有效长度。
- 校准使用单独的版本化单声道缓冲，保留原来对输入左右求平均的校准定义。校准缓冲不能附加为循环轨道，错误布局会被拒绝。

## 功能验证

完整检查通过：53/53 单元测试、类型检查、生产构建、3/3 UI 测试，以及 Chromium 149 的 23/23 软件音频检查。构建输出中的 Worklet 与实测源码 SHA-256 相同。

真实 Worklet 源码测试覆盖左右不同波形、单侧输入、反相输入、单声道输入、循环环绕、正反向叠录与位置补偿、块内指定采样帧录音起点、清除后重录、EMPTY/STOPPED 静音和时钟推进。Runtime 测试验证旧握手拒绝、并发准备、失败重试，以及逐样本正确的双声道导出。立体声源反相时两边仍分别保留，避免旧平均路径将其消掉。

Chromium 检查运行实际应用和 AudioWorklet，使用合成 MediaStream 输入与静音软件输出。五轨均导出两个声道；左侧 250 Hz、右侧 500 Hz 在存储和最终 master 播放输出中仍分别占主导：

| 软件检查 | 数值或结果 |
| --- | --- |
| Track 1 导出左声道：250 Hz / 500 Hz 分量 | 0.09956 / 0.000880 |
| Track 1 导出右声道：500 Hz / 250 Hz 分量 | 0.08018 / 0.000704 |
| 最终播放左声道：250 Hz / 500 Hz 分量 | 0.29909 / 0.004477 |
| 最终播放右声道：500 Hz / 250 Hz 分量 | 0.23786 / 0.003581 |
| 叠录改变的左右样本数 | 左 6,016；右 6,016 |
| 合成单声道音源导出：左右最大样本差 | 0 |
| Filter UI 高/低截止频率的输出 RMS 比 | 32.76，超过原检查阈值 4 |

频率分量是有限长度分析窗计算出的数值，存在频谱泄漏；不能当作声卡电气串音测量。合成单声道音源对应的最终采集流设置仍报告 2 声道，因此该浏览器检查证明同声源的左右一致性；直接单声道输入的复制行为由真实 Worklet 源码测试另行验证，不声称验证了物理单声道设备。

播放声道检查把 Analyser 的窗口扩大到 8,192 帧（48 kHz 下约 171 ms）。原来 Filter 参数变化后等待 100 ms 会混入旧样本而产生假失败，最终改为等待 300 ms 后再测量，检查阈值未放宽。UI mocks 仅用于界面测试，不能替代上述真实源码和 Chromium 检查。
