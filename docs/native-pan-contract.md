# Native track PAN contract

Native PAN uses integer values from -50 (left) to 50 (right), with 0 as center. Roland's [RC-505mkII Parameter Guide](https://static.roland.com/assets/media/pdf/RC-505mk2_Parameter_eng04_W.pdf), page 2, lists L50–CENTER–R50. The `webaudio-stereo-v1` law is an engineering compatibility choice based on the [Web Audio StereoPanner algorithm](https://www.w3.org/TR/2021/REC-webaudio-20210617/#stereopanner-algorithm); the guide does not specify a hardware pan law, and this implementation is not a hardware measurement.

A PAN-capable host exposes `nativeTracks[].pan` with `requested`, `applied`, `requestedRevision`, `appliedRevision`, and `law`, and `nativeMemory.trackPans` with five authored values. The Memory snapshot is valid for capture only after all PAN revisions have settled and each authored value matches its callback-applied value; the UI uses the per-track applied readback for confirmed values. Memory capture checks revisions again after PCM capture. Pending or unresolved PAN operations block capture and switching. Partial capability or mismatched readback is refused.

`POST /v1/native-track-pan/config` requires a matching `X-Native-Host-Incarnation` header and `{trackId, pan, expectedRevision}`. The renderer must be running. The host validates track 1–5, integer PAN, revision and existing snapshot/Memory fences before accepting a compare-and-swap. The response identifies `acceptedRevision`; only matching callback-applied revision and value completes the client operation. The callback owns coefficients and installation; the control thread cannot manufacture an applied ACK while stopped. Center uses the previous single-pass fader/meter/mix path exactly; nonzero PAN operates on gained stereo playback before its shared-FX/bypass bus. Input recording, direct monitoring, and the pre-insert Bounce source tap retain their paths.

Before POST, the client retains a session receipt bound to host and expected revision. Lost replies and generic HTTP 400/5xx remain uncertain; status reconciliation sends GET only. Once a newer applied PAN revision is confirmed, the old CAS can no longer change that host, so its guard can be released without claiming ownership of somebody else's write. A new explicit user edit may submit a new CAS; there is no automatic mutating retry. Definite 409 rejection removes only its own receipt. Storage errors fail closed before submission or retain uncertainty. Memory blocks on both local guards and host pending revisions.

Classic edits retain backend, host and revision context. A delayed event after a backend/host/Memory change is rejected before POST instead of rebinding onto the new state. Old or incoherent host readback displays `UNAVAILABLE`, not a proxy's stale PAN. The numerical law applies to the existing Native stereo stream; no new pan smoothing, algorithmic delay, or Roland binary format is claimed.

Native semantic Memory stores the five values in `WEBRC.nativeMemory.trackPans` and supported `track.N.pan` semantic fields. Import validates both representations, capability, and readback; it waits for same-host PAN and Memory acknowledgements before installing local state. A legacy Native semantic Memory without PAN restores center on a PAN-capable host. Older hosts without either PAN readback retain their unsupported semantics and cannot restore a PAN-bearing Memory. Raw PCM archive import retains its existing semantics.
