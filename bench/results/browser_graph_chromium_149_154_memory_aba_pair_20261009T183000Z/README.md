This pair shows fewer recorded forward timeline gaps in the Chrome 154 arm, but gaps remained in both arms. The Worklet diagnostic event ring overflowed in both runs, so its event capture is incomplete and does not support attribution of the gaps to individual Memory operations. This is an observational version comparison; it does not prove that a Chromium change caused the difference or that A–B–A eliminated the discontinuities.

Each arm captured one filtered Chrome trace window using `audio`, `webaudio`, `disabled-by-default-audio`, `disabled-by-default-audio-worklet`, and `disabled-by-default-v8.gc`, with excluded category `*`; each reports no trace data loss and complete coverage for one audio TID. Worklet script-callback P99/P99.9/max were 909/1112/1324 μs on Chrome 149 and 827/1056/1410 μs on Chrome 154. The traces do not measure the complete AudioRenderTask or external device deadline, and these callback timings are not full-graph timing qualification. The test is a one-minute diagnostic, not the 30-minute Gate 7 stress test and not a hardware XRUN test.
